## Security considerations

Read with: `AGENTS.md` (Runtime invariants: Bypass mark, Netns discipline, NFQUEUE ownership); `deployment.md`; `configuration.md` for the settings named here.

- **Root/privileged execution:** `honk-core` requires root for the operations listed under `deployment.md`.
- **Clash API secret:** when `experimental.clash_api` is enabled, set a strong `secret`; the REST/WS API has no TLS of its own — bind to localhost or front it with a reverse proxy.
- **Native API:** credentials and HTTP boundaries are independent of Clash. Bearer is required even for bootstrap and same-origin UI API requests; anonymous mode must be explicitly enabled on loopback with an empty secret, and never accepts invalid credentials. Host/Origin allowlists use canonical authorities and explicit origins, not forwarded headers. Public UI assets still require the deployment boundary. Native HTTP has no TLS; do not expose anonymous loopback via a proxy or call non-loopback plaintext bearer secure. API request logs contain templates, method/status/time and generated IDs, never raw paths, queries, tokens, bodies or engine errors.
- **Native source writes:** whole-source administration is privileged. Never expose credentials or offer redacted content as editable text. Native settings, Clash secret and credential-source membership/bytes cannot be changed through API writes. Open parents/files without symlink traversal; retain the parent FD, preserve mode, write/fsync an exclusive temporary, recheck target identity/hash and dependency topology/bytes after candidate validation, then renameat and fsync the directory. External editors remain uncoordinated between the final check and rename. Distinguish pre-rename failure from visible-but-not-durable replacement; never claim rollback after rename. Keep accepted operations daemon-owned across HTTP cancellation and replay retained idempotency keys before disk preconditions.
- **Native diagnostics and logs:** probes use configured targets, independently authorize resolved CIDRs and ports, and pin the actual address through marked transport admission. Never fall back around a typed refusal or report discarded health publication as accepted. Native logs capture structured audited fields, withholding untrusted message/Debug/Display values rather than formatting and trying to redact them. Group source ETags are accepted configuration revisions, not disk-content hashes; recheck them under reload publication ownership.
- **Config trust:** treat config/BPF objects as privileged input. `honk-core` writes `/proc/sys` directly and loads configured/CLI BPF paths. Netns/link/routes/rules use rtnetlink and an FD-owned namespace, requiring no external `ip`/`nsenter`.
- **Bypass mark discipline:** follow the **Bypass mark** rule in `AGENTS.md` (Runtime invariants) for `DAE_BYPASS_MARK`; missing marks loop gateway traffic.
- **NFQUEUE ownership:** host-netns firewall automation must honor `crates/honk-nfqueue`'s exact-name/no-bypass rules while enabled. Mutation can fail closed or violate held-skb lifecycle assumptions.
- **Subscription store trust:** `subscription/store.rs` retains a validated directory FD for every read, write, rename, cleanup, and sync; the original path is diagnostic-only after open. Reject foreign-owned or group/other-writable directories and cache files before changing permissions. Open directories and cache files without following the final symlink; validate cache-file ownership and regular-file type on the opened FD. Never replace descriptor-relative operations with fresh pathname resolution.
