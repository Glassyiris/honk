# 迁移到 v0.1.0-beta.3

适用于从 `v0.1.0-beta.2` 升级的场景。只列出会影响已有配置或运维预期的变更；
每个版本的迁移说明与本文件并列存放。

## 1. 升级前必读

| 变更 | 处理方式 |
| --- | --- |
| `lan_interface` / `wan_interface` 中的 `auto` 现在还会匹配大写、带空白和仅含空白的条目（例如带引号的 `" "`）。 | 删除并非有意指向默认路由网卡的写法。 |
| 网卡存在即绑定，不再要求 `IFF_UP`。 | 无需操作。 |
| 配置的 `vrf` 或 `openvswitch` master 的成员绑定在其自身，不再提升为 master。其他 master（`bond`、`bridge`、`team` 等）的成员仍解析为该 master。 | 请直接写出要拦截的网卡。 |
| LAN 与 WAN 角色按网卡各自确定：同时出现在两个列表中的名称是 LAN/WAN 共用网卡，不再让其他 LAN 网卡丢失反向 hook。 | 无需操作。 |
| `lo`、`vcan`、InfiniBand、非点对点 GRE、直接配置的 `vrf`、`dae0` 与 `dae0peer` 现在以 `unsupported_type` 被拒绝，而不再被挂上按错误偏移解析的程序。启动继续。 | 替换该条目（`vrf` 请改配其成员）。 |
| 网卡不存在、`auto` 未解析、类型被拒绝或 TCX 挂载失败，不再导致启动失败。该项不绑定任何 hook（或只绑定部分 hook），`GET /runtime` 报告 `interface_binding` 降级，而 `lifecycle.state` 仍为 `running`。位于尚不存在的网卡上的 `dns.bind` 仍会使启动失败。 | 对 `interface_binding` 降级告警；`running` 并不表示所有已配置网卡都已被拦截。 |
