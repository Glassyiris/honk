# Migrating to v0.1.0-beta.3

Applies when upgrading from `v0.1.0-beta.2`. Only changes that affect an existing
configuration or operator expectation are listed; per-release files live beside this one.

## 1. Before you upgrade

| Change | What to do |
| --- | --- |
| `auto` in `lan_interface` / `wan_interface` also matches upper-case, padded and whitespace-only entries (for example a quoted `" "`). | Remove any entry whose spelling you did not intend to mean the default-route interface. |
| An interface is bound as soon as it exists; the `IFF_UP` requirement is gone. | Nothing. |
| A configured member of a `vrf` or `openvswitch` master is bound on itself, not promoted to the master. Members of other masters (`bond`, `bridge`, `team`, ...) still resolve to the master. | Name the interface you want intercepted. |
| An entry in `lan_interface` / `wan_interface` whose master path is rejected as unsupported bond/bridge nesting, or that is its own master, fails startup, wherever it appears in the list. | Name a supported root interface, or flatten the nesting; see [Interface hook sets](../../en/design/datapath.md#interface-hook-sets). |
| LAN and WAN roles are per interface: a name in both lists is a shared LAN/WAN interface and no longer strips the reverse-direction hooks from the other LAN interfaces. | Nothing. |
