# Migrating to v0.1.0-beta.3

Applies when upgrading from `v0.1.0-beta.2`. Only changes that affect an existing
configuration or operator expectation are listed; per-release files live beside this one.

## 1. Before you upgrade

| Change | What to do |
| --- | --- |
| `auto` in `lan_interface` / `wan_interface` also matches upper-case, padded and whitespace-only entries (for example a quoted `" "`). | Remove any entry whose spelling you did not intend to mean the default-route interface. |
| An interface is bound as soon as it exists; the `IFF_UP` requirement is gone. | Nothing. |
| A configured member of a `vrf` or `openvswitch` master is bound on itself, not promoted to the master. Members of other masters (`bond`, `bridge`, `team`, ...) still resolve to the master. | Name the interface you want intercepted. |
| An entry in `lan_interface` / `wan_interface` with unsupported bond/bridge nesting or a self-master is refused as `unsupported_type`; other configured entries still bind at startup and reconcile normally, instead of starting with no configured hooks and `pending` or freezing all bindings during reconciliation. | Name a supported root interface, or flatten the nesting; monitor `interface_binding` even while `lifecycle.state` is `running`. See [Interface hook sets](../../en/design/datapath.md#interface-hook-sets). |
| LAN and WAN roles are per interface: a name in both lists is a shared LAN/WAN interface and no longer strips the reverse-direction hooks from the other LAN interfaces. | Nothing. |
| `lo`, `vcan`, InfiniBand, non-point-to-point GRE, a `vrf` named directly, `dae0` and `dae0peer` are refused as `unsupported_type` instead of being mounted with a program that parsed the wrong offset. Startup continues. | Replace the entry (for a `vrf`, name a member). |
| A missing interface, an unresolved `auto`, a refused type or a TCX attach failure no longer fails startup. The entry binds nothing (or only part of its hooks) and `GET /runtime` reports the `interface_binding` degradation while `lifecycle.state` stays `running`. A `dns.bind` on an interface that does not exist yet still fails startup. | Alert on the `interface_binding` degradation; `running` does not show that every configured interface is intercepted. |
